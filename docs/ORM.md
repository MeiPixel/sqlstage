# ORM：查询对象而不只是字符串

ORM 路径让模型生成查询意图，由本地规则编译 SQL。已有查询保存为对象，追问只描述增量，不要求每次重写整个 JOIN 和过滤逻辑。

对象使用方式示意（自然语言到增量代码由模型接口完成）：

```python
from sqlstage.query_object import table

query = table("products").filter(price__lt=50).select("name", "price").order_by("-price")
query = query.filter(brand="Acme")
print(query.sql())
```

第二次赋值得到新对象，原对象不被修改。实际支持的操作以 `QueryObject` 白名单为准；模型返回的 Python 片段通过 AST 解释，不使用任意 `eval/exec`。

## 业务规则

| 配置 | 用途 |
| --- | --- |
| 字段联动、必返字段 | 触发一个业务条件时补上必要条件或输出字段 |
| 值映射、字段别名 | 把业务说法映射到数据库字段与取值 |
| 单位与数值转换 | 统一单位，处理数字以文本存储的字段 |
| 精确/包含/前缀匹配 | 按字段固定 `=`、`LIKE` 匹配策略 |
| JOIN 规则 | 按业务字段补上已配置的关联关系 |
| 派生字段、指标 | 固定计算口径，避免不同问法产生不同算法 |
| 向量字段值纠正 | 目前是本地字符 n-gram 相似度配合编辑距离阈值，不是预训练语义向量 |
| 参数模板 | 将既有筛选值参数化，后续传参后在本地编译 |

业务规则应来自业务定义，而不是为提高测试集分数追加题目没有要求的筛选。关联关系需与数据库一致，模板仅适合结构相同的查询。

## Token 口径

首页和对象接口展示 API 返回的实际 Token，不用估算字符数替代。自然语言追问如“只看 Acme”仍调用模型输出 `query = query.filter(...)`，因此有新增 Token；不是零成本操作。

只有已建立的模板参数绑定是纯本地步骤，无新增模型 Token。ORM 是否比直接 SQL 省 Token、是否准确，要用相同问题、同样上下文和规则比较；不能保证所有查询都受益。

对象 API：`POST /api/orm/object`；模板 API：`POST /api/orm/template`。请求结构可在后端 `/docs` 查看；UI 提供规则与对象操作，无需用户手写计划 JSON。
